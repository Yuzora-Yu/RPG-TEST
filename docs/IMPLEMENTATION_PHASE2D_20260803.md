## 1. 本フェーズの範囲

本フェーズでは、旧深淵ボスの完全削除と旧セーブ救済を先に行い、その後、深淵101階以降のボス強化ロジックを再設計した。

実装済み:

- モンスターID `401010`～`401100` のマスター・実行時参照削除
- 削除済みIDが旧セーブ内に残る場合の参照除去
- `302101` 討伐済みセーブに対する `302000`・`302001`・`302100` 討伐数救済
- カルメナ北門進行フラグと門将討伐記録の整合性修復
- カルメナ北門クリアイベントの討伐数再確認
- 宝箱トラップのログ表示と演出ウェイトの順序修正
- 深淵101階以降のボス強化用スキル系統マスター新設
- 元スキル・元耐性・元特性を基準とする深層ボス強化
- 役割別のボス追加特性プール新設
- 固定乱数による互換・深層ボス生成テスト追加

未実装:

- ストーリーボス訓練所

## 2. 旧深淵ボスの完全削除

### 2.1 削除範囲

次の範囲を互換用マスターとしても残さず、正式に削除した。

```text
401010～401100
```

実際に存在していた削除レコードは次の12件。

```text
401010, 401020, 401030, 401040, 401050, 401060,
401070, 401080, 401081, 401082, 401090, 401100
```

`monsters.js` のモンスター総数は348体から336体になった。

### 2.2 関連参照

以下から削除IDを除去した。

- モンスターマスター
- 深淵旧固定ボスイベント
- 深淵旧固定ボス表示処理
- ギルド依頼ボスのフォールバック
- 戦闘側ボス候補・特殊表示判定
- BGM特殊ボス判定
- 深淵モンスターマニフェスト

新しいフォールバックには、現行マスターに存在する `401200` を使用する。

### 2.3 旧セーブの残留参照

ロード・インポート移行時に、削除範囲が次へ残っていれば除去する。

- 図鑑登録
- 討伐数
- 進行中戦闘の固定ボスID・敵配列
- 深淵ボス遭遇データ
- 生成済みギルド依頼のボスID

削除対象しかいない進行中戦闘は、空の戦闘として再開せず終了状態へ戻す。

ソース内に削除範囲の数値判定が残るのは、この旧セーブ清掃処理だけである。

## 3. 深淵ボス討伐数の互換処理

### 3.1 救済条件

図鑑討伐数で `302101` が1体以上の場合、初回の移行時だけ次の討伐数を最低1へ補完する。

- `302000`
- `302001`
- `302100`

既存値が1以上の場合は減らさない。

完了フラグ:

```text
system.abyssBossKillCountRecoveryV1Completed
```

`302101` が未討伐のセーブでは完了フラグを立てないため、将来討伐後のロード時に救済を適用できる。

### 3.2 目的

- 旧バロン・フリーダ関連戦闘によるカルメナ進行誤作動の救済
- 旧形態移行戦で `302100` が討伐数へ記録されなかったセーブの救済

## 4. カルメナ進行の整合性

カルメナ北門は、フラグ単独ではなく `302000` と `302001` の討伐数を正本として扱う。

### 4.1 正規クリアとして補完する条件

次のいずれかを満たす場合、門将2体の討伐数を最低1へ補完し、`abyssCarmenaGateCleared` を有効化する。

- 門将2体を討伐済み
- カルメナ以降の深淵ボス討伐記録が存在
- カルメナ以降の深淵進行フラグが存在
- カルメナクリアフラグがあり、門将のどちらかを討伐済み

後続進行が存在する場合は、カルメナフラグ自体が欠落していても復旧する。

### 4.2 誤作動として解除する条件

後続進行も門将討伐もないのに、カルメナクリアフラグだけが存在する場合は次を行う。

- `abyssCarmenaGateCleared` を解除
- カルメナ北門の門将座標を撃破済み記録から除去
- 門将が再表示・再戦可能な状態へ戻す

### 4.3 イベント側の二重防御

`abyss_carmena_gate_clear` は、勝利後に門将2体の討伐数を再確認する。

2体分の記録が揃っていない場合は、会話とクリアフラグ設定を実行しない。

新しいイベントアクション `IF_KILL_COUNTS` は、イベントジャーナル管理下と通常イベント処理の両方に対応している。

## 5. 宝箱トラップの表示順

従来は演出ウェイトの後に襲撃ログが表示される経路があった。

現在は次の順序へ統一した。

1. 宝箱を開封
2. トラップモンスター襲撃ログを即時表示
3. 驚き演出のウェイト
4. 戦闘データ確定
5. 戦闘画面へ遷移

固定宝箱とランダム迷宮の擬態箱の両方が、共通の非同期処理を使用する。

## 6. 深淵101階以降のボス強化

### 6.1 旧処理の問題

旧処理では、深層ボスに対して次を行っていた。

- 元の属性耐性を無視して全属性をランダム化
- 元技と無関係な高MP技をランダム追加
- 武器以外の全特性から無関係な特性を追加

これを廃止した。

### 6.2 正式マスター

`abyss_content.js` に次を追加した。

- 深層ボス用スキル系統: 62系統
- 役割別追加特性プール: 6役割
- 状態異常耐性の強化対象キー

スキル系統は、物理・魔法・ブレス・回復・蘇生・強化・弱体・状態異常を、属性・対象・性質ごとに弱い技から強い技の順で明示している。

ゲーム実行時に全スキルマスターを書き換える処理はない。

### 6.3 使用スキル

- 元ボスの使用技は全て維持
- 元技が正式な系統に属する場合だけ、同じ系統の上位技を候補化
- 階層に応じて上位段階を進める
- 追加数は最大3技
- 元技と無関係な技は追加しない
- 元技がすでに系統最上位の場合は無理に別技を追加しない

追加技には、元技IDと系統IDを生成データ上へ記録する。

### 6.4 特性

元特性は削除せず、階層段階に応じて特性Lvを上げる。

基礎能力と元スキルから次の役割を判定する。

- 物理
- 魔法
- ブレス
- 防御
- 速攻
- 支援

追加特性は該当役割のプールからだけ抽選する。

次は追加プールへ含めていない。

- 武器そのものの習熟特性
- 探索・宝箱・ドロップ特性
- 大器晩成
- 武の極み
- 魔の極み

### 6.5 耐性

状態異常耐性と属性耐性は、元マスター値を維持して階層分を加算する。

例:

- 元の火耐性70、追加15 → 85
- 元の水耐性-20、追加15 → -5
- 元データにない属性0、追加15 → 15

弱点を無関係なランダム耐性へ置き換えることはない。

### 6.6 保存互換

生成済み戦闘・遭遇の敵スナップショットは従来どおり保存内容を優先する。

新規生成された深層ボスには次を記録する。

```text
deepEnhancementVersion: 2
```
