## 2. 成長処理

### 2.1 転生・合成回数の共通化

通常仲間は `reincarnationCount`、仲間モンスターは `monsterFusionCount` を参照し、内部では同じ「育成周期回数」として扱う。

共通取得関数:

- `App.getReincarnationEquivalentCount()`
- `App.getReincarnationGrowthMultiplier()`

成長倍率は旧仕様の「1回につき+100%」から次へ変更した。

```text
成長倍率 = 1 + min(育成周期回数, 5) × 0.10
```

| 転生・合成回数 | 成長倍率 |
|---:|---:|
| 0 | 1.0倍 |
| 1 | 1.1倍 |
| 2 | 1.2倍 |
| 3 | 1.3倍 |
| 4 | 1.4倍 |
| 5以上 | 1.5倍 |

必要経験値、成長倍率、転生条件付きスキルツリー判定で同じ育成周期回数を参照する。

### 2.2 大器晩成・成長特性

- 大器晩成は全能力の最終成長量へ乗算するよう変更した。
- HP・MPだけ効果が実質半分になっていた旧計算を解消した。
- 武の極み、魔の極みは従来どおり該当能力へ加算する。
- 永続成長では本人が習得した特性だけを参照する。
- 装備に付いた成長特性をレベルアップ直前だけ装備して永続能力を増やすことはできない。

### 2.3 魔防二重加算

レベルアップ1回につき `incMdef` が2回加算される箇所があったため、1回だけ加算するよう修正した。

### 2.4 未調整項目

次は既存仕様のまま残している。

- Lv50・Lv100の5～6倍成長
- 通常レベルアップ時12%のひらめき成長
- 1戦で複数レベル上昇可能な処理

1戦での過剰レベルアップは、次フェーズ以降に敵・ボスの経験値マスターを直接調整して解消する。

## 3. 仲間モンスター成長型

### 3.1 成長型マスター

`monsters.js` に `MONSTER_ALLY_GROWTH_TYPE_MASTER` を追加した。

実装した24型:

- 守備特化型A・B・C
- 魔防特化型A・B・C
- 守備・魔防特化型A・B・C
- 魔力特化型A・B・C
- 攻撃特化型A・B・C
- 攻撃・魔力特化型A・B・C
- 速さ特化型A・B・C
- バランス型A・B・C

特化型の目安:

- A: 特化能力が非特化能力の約1.5倍
- B: 約2倍
- C: 約5倍

総成長量が型だけで大幅に増えないよう、攻撃・守備・魔力・魔防・速さの合計成長予算を正規化し、その中で配分差を作っている。

### 3.2 バランス型

- バランス型A: 戦闘能力がほぼ同等
- バランス型B: 緩やかな物理型
- バランス型C: 緩やかな魔法型

### 3.3 HP・MP参照元

- バランス系: 主人公アルス（ID 301）
- 物理系: ガイル（ID 109）
- 魔法系: サラ（ID 110）

守備・魔防複合型および攻撃・魔力複合型はバランス参照、速さ型は物理参照としている。

### 3.4 モンスターマスターへの設定

全348体の各モンスターレコードへ `allyGrowthType` を直接追加した。

ゲーム実行時に能力値から成長型を推測したり、マスターデータを上書きしたりしない。

`tools/assign-monster-growth-types.js` は開発時に既存マスター能力を解析してレコードへ設定するための補助ツールであり、ゲーム実行時には読み込まれない。

旧セーブの仲間モンスターは、ロード時の一度限りのスキーマ移行で、元モンスターIDに対応する明示成長型へ移行する。現在能力、レベル、スキル、特性は変更しない。

## 4. モンスター育成所

### 4.1 配置

レガシオンの座標 `(15, 25)` に新規施設として追加した。
格闘場予定地とは別施設であり、既存の格闘場予定地は変更していない。

施設背景は暫定で既存施設画像を使用する。

### 4.2 初回配布

施設へ初めて入った時、1セーブにつき1回だけ合成の壺を1個入手する。

保存フラグ:

```text
progress.flags.monsterNurseryFirstVisitGiftReceived
```

### 4.3 合成仕様

- メイン1体、素材1体を選択
- パーティ編成中でも両方選択可能
- 合成の壺を1個消費
- 素材モンスターは消滅
- 合成後はLv1、経験値0
- メインの名前、画像、成長型を維持
- 永続能力は `メイン + floor(素材 × 10%)`
- 装備補正・戦闘中補正は能力加算の対象外
- 両者の装備をすべて解除して所持品へ戻す
- 合成後は最大HP・MPまで回復
- メインのSP、スキルツリー、LB情報を維持
- 合成回数を1増加
- 合成回数を通常仲間の転生回数と同じように必要経験値・成長補正・転生条件付きツリーへ反映

### 4.4 スキル

- 両者のスキルを統合
- 重複は1枠
- 8個以下ならすべて引き継ぐ
- 8個を超える場合は画面で8個を選択

### 4.5 特性

- 両者の特性を統合
- 同一特性は高いLvを採用
- 同Lvの場合は蓄積戦闘回数が高い方を採用
- 6個以下ならすべて引き継ぐ
- 6個を超える場合は画面で6個を選択

## 5. 特性書の7枠目

- レベルアップによる自然習得は従来どおり最大6個
- 特性を6個所持している場合だけ、特性書で7個目を追加可能
- 追加される特性はLv1
- 7個所持時は従来の交換UIを使用
- 6個未満で特性書を使う場合も、従来どおり交換扱い

これにより、特性書を早期使用して自然習得6枠を圧迫することを防いでいる。

### 検証上の制約

この実行環境では、管理ポリシーによりChromiumからローカルURLおよび `file://` への遷移が遮断された。そのため、ブラウザ上の目視・タップ操作テストは実施できていない。

添付ZIPでは大容量assetsが除外されているため、画像ファイルの存在を前提とする既存バリデーターは原本の時点から失敗する。また、一部の既存バリデーターは現在のマスター・マップ定義と期待値が同期しておらず、原本でも同じ失敗を確認した。

実機・通常ブラウザでは、特に次を確認すること。

1. レガシオン `(15,25)` の育成所入口
2. モーダル内の長いスキル・特性一覧の操作
3. 合成後の装備返却とパーティ表示
4. 錬金所のスクロール保持
5. ルーナ撃破直後・マップ移動後・セーブ再開後の画像
6. 各スカイプリズム移動先での即時アクション表示
