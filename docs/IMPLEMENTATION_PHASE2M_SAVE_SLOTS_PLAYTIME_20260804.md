外部ファイル／フォルダへの継続書込と権限連携は、今回実装していない。ゲーム内10枠には認証・フォルダ権限を要求しない。

## 2. セーブスロット画面

各枠を次の構造で表示する。

- 左1行目: `オート` または `No.1～9`、保存日時。
- 左2行目: 主人公名、レベル。
- 左3行目: 現在エリア、プレイ時間。
- 右3行分: 現在の編成順で最大4名の顔グラフィック。

空き枠はロード不可。オート枠は手動保存先として選択不可。仲間モンスターはキャラクター顔画像ではなく、保存されているモンスター画像を優先する。

## 3. 保存方式と安全処理

### 3.1 オートセーブ

既存 `App.save()` の同期契約を変更していない。戦闘・報酬・装備・通貨等の既存235呼出箇所は、従来どおり成功／失敗を同期的に受け取る。

### 3.2 手動セーブ

`save_slots.js` がIndexedDB `PRISMA_ABYSS_SAVE_SLOTS` の `slots` ストアを管理する。

保存レコード:

- `slotId`
- `schemaVersion`
- `updatedAt`
- 表示用メタデータ
- 完全セーブJSON `payload`
- SHA-256、利用不可時はFNV-1aの整合性検査値

手動上書きでは旧レコードを先に退避し、書込後の再読込・整合性確認に失敗した場合は旧レコードへ戻す。空き枠への初回保存失敗時は、不完全な新規レコードを削除する。

### 3.3 手動ロード／バックアップ読込

- 手動ロード前にチェックサムとJSON形式を検証。
- 現在のオート枠を一時退避。
- 互換移行後のデータをオート枠へ同期書込。
- 再読込・再解析に成功した場合だけゲームを開始。
- 失敗時は元のオート枠へ戻す。
- 元の手動枠は変更しない。

バックアップ読込も同じオート枠書込処理を通す。現在のオート枠が即時上書きされることと、手動No.1～9は変更されないことを確認画面に表示する。

### 3.4 IndexedDB利用不可時

手動9枠だけを利用不可にする。オートセーブ、既存データ出力、既存データ読込は維持する。

## 4. タイトルと設定画面

### タイトル

- `オートセーブから`: 最新オート枠を直接開く。
- `つづきから`: 10枠一覧を開く。
- 手動枠選択時: オート枠が即時上書きされることを警告。
- `はじめから`: 既存オート枠がある場合だけ警告し、手動枠を残して新規開始。
- データ管理: 現在のオート枠のバックアップ出力／オート枠へのバックアップ読込。
- オートセーブ削除: 手動1～9は削除しない。

### 設定

- `設定`: 既存の戦闘速度、オート戦闘、音量設定。
- `セーブ`: セーブ、ロード、データ出力、データ読込、一括ダウンロード。

`一括ダウンロード`は従来のゲーム画像等の全データキャッシュ機能であり、10枠セーブ一括出力ではない。

## 5. プレイ時間

### 保存・移行

- 正本: `stats.playTimeMs`。
- 旧セーブは `startTime` から推測せず、導入後0から開始。
- 内部値は減らさない。
- 表示形式: `hhhh:mm:ss`。
- 表示上限: `9999:59:59`。

### カウント範囲

- ゲーム本編ページが前面表示されている時間だけ加算。
- タイトル、非表示タブ、バックグラウンド中は加算しない。
- 1秒ごとに画面表示だけ更新。
- 永続化は既存 `App.save()` のタイミングで行い、プレイ時間だけを理由に戦闘中等で新規保存を発生させない。

既存保存後からブラウザを強制終了するまでの未保存時間は、最後の正常オートセーブ以降分が残らない可能性がある。進行安全性を優先し、`pagehide`だけを理由にゲーム本体を上書きする処理は追加していない。
