# PRISMA ABYSS Phase2J 戦闘結果ホットフィックス報告

作成日: 2026-08-04  
基準: GitHub `main` commit `038583c052a5098dfe7f2b99501eae5e0b5ba6de`

## 1. 対象症状

通常戦闘を含め、敵を全滅させた直後に以下を繰り返す。

1. 敵が全員復活する
2. オート戦闘が解除される
3. 再度全滅させても同じ状態へ戻る

## 2. 根本原因

Phase2Iでランダム迷宮特殊階層の `rareDropMultiplier` と `equipPlus3BonusPct` を戦闘データへ保存する処理が追加された。

しかし、勝利報酬処理 `Battle.win()` では `rareDropMultiplier` をローカル変数へ取り込まないまま参照していた。

そのため、敵全滅後の勝利確定時に次の例外が発生する。

```text
ReferenceError: rareDropMultiplier is not defined
```

戦闘結果処理には、報酬処理中の失敗時に結果を巻き戻し、保存済み戦闘スナップショットから戦闘を再構築する安全処理がある。この復旧処理は手動操作へ退避するため、結果として「敵全復活＋オート解除」という見え方になっていた。

## 3. 修正内容

### battle.js

- `Battle.getBattleRewardRateModifiers()` を追加。
- `App.data.battle` の次の値を勝利処理へ正式に引き渡す。
  - `rareDropMultiplier`
  - `equipPlus3BonusPct`
- 未設定の旧セーブ・通常戦闘では以下へフォールバック。
  - レアドロップ倍率: `1`
  - +3装備抽選加算: `0`
- 負の値は0へ制限。
- Phase2Iの「強敵の財宝階 +3抽選+20ポイント」も勝利報酬処理へ接続。
- 戦闘結果ジャーナル、ロールバック、固定ボス、形態移行の仕組みは変更しない。

### news.js

2026/08/04の既存レコードへ次の1行を追記。

```text
・戦闘勝利時に敵が復活する不具合を修正しました
```

### main.js / sw.js

Service Workerキャッシュを `v40.20260804` へ更新し、`main.js` と `sw.js` のランタイムキャッシュ名を同期。

## 4. 適用方法

現在のGitHub作業ツリーのルートで実行する。

```bash
node tools/apply-phase2j-battle-result-hotfix.js .
node tools/test-phase2j-battle-result-hotfix.js .
```

適用前確認だけを行う場合:

```bash
node tools/apply-phase2j-battle-result-hotfix.js . --check
```

スクリプトは同じ修正を二重追加しない。

## 5. 検証

専用試験で以下を確認する。

- 報酬倍率ヘルパーが存在する
- 通常戦闘の既定倍率が `1 / 0`
- 特殊階層の `2 / 20` が維持される
- 負数が0へ制限される
- `rareDropMultiplier` が使用前に必ず定義される
- スキル書ドロップにも同倍率が渡る
- +3装備抽選加算が接続される
- 戦闘結果失敗時の安全復旧処理を削除していない
- news.jsへ同日追記される
- main.js / sw.jsのキャッシュ名が一致する

## 6. 実機での最優先確認

1. 通常敵1体をオートで撃破し、結果画面へ移行する
2. 通常敵複数をオートで撃破し、敵が復活しないことを確認する
3. レアドロップを持たない敵でも勝利できることを確認する
4. レアドロップを持つ敵でも勝利できることを確認する
5. ボス形態移行後の最終勝利を確認する
6. ランダム迷宮「強敵の財宝階」で報酬確定を確認する
7. 戦闘結果表示中に再読込し、結果ジャーナルが重複しないことを確認する
