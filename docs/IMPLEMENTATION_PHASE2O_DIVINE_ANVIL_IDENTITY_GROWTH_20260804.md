# IMPLEMENTATION Phase2O 神鉄の鍛冶台・装備個性保持Rank強化

作成日: 2026-08-04

## 1. 対応目的

神鉄の鍛冶台を使用した際、従来は同じ部位・武器種の上位装備マスターへ装備そのものを変換していた。
この方式では、お気に入り装備の名称、固有特性、固有スキル、装備固有の補正が失われるため、装備の個性を保ったまま長期育成できる仕様へ変更した。

代表例:

- 変更前: 「ドラゴンキラー+3」が上位Rankの別名剣へ変換され、ドラゴンキラー固有特性も変化する。
- 変更後: 「ドラゴンキラー+3」の名称・特性・オプションを維持し、Rankと基礎能力だけが上がる。

## 2. 新しい正式仕様

### 2.1 対象装備

従来の対象条件を維持する。

- 通常装備であること。
- `specialEquip`、`noRandom`、真・装備は対象外。
- 同じ部位・`baseName`に上位の通常装備Rank基準が存在すること。
- 最高段階で上位基準がない装備は対象外。

### 2.2 Rank上昇

- 現在Rank+10を目標にする。
- 同じ部位・`baseName`の正式装備マスターから、目標に最も近い上位Rankを選ぶ。
- 2回目以降は元マスターのRankではなく、装備インスタンスに保存された現在Rankから続ける。

例:

- Rank50 → Rank60
- 続けて使用した場合 Rank60 → Rank70

### 2.3 維持する情報

神鉄使用前後で以下を変更しない。

- 装備UID `id`
- 正式装備識別子 `eid` / `masterEid`
- 名称
- 部位と武器・防具種 `type` / `baseName`
- +値
- 固有特性とランダム特性を含む `traits`
- ランダムオプション `opts`
- オプション候補 `possibleOpts`
- 固有スキル `grantSkills`
- ロック状態
- レアリティ、入手元、独自メタデータ
- 装備中の所有者との接続

確定処理で変更するのは以下だけである。

- `rank`
- `data`
- `val`

### 2.4 基礎能力の成長

成長対象は鍛冶正式マスターの `scalableStatKeys` を正本とする。

- `atk`
- `def`
- `mag`
- `mdef`
- `spd`
- `hp`
- `mp`

成長方法:

1. 同じ能力キーが現在Rank基準と次Rank基準の双方にある場合、その正式マスター間の伸び率を現在個体へ適用する。
2. お気に入り装備だけが持つ成長能力で次Rank基準に同じキーがない場合、同系統装備の正の基礎能力総量の伸び率を使用する。
3. 総量基準でも伸びが取れない場合はRank比率を使用する。
4. 正の成長対象能力は最低1上昇させる。
5. 負の補正は装備固有の欠点として維持し、悪化させない。

変更しない固有値:

- 命中
- 会心
- 回避
- 属性攻撃・属性耐性
- 状態異常付与・耐性
- その他の非成長キー
- ネストした補正データ

これにより、ドラゴンキラーの命中+10や固有特性を維持しながら、攻撃力だけを剣のRank推移に合わせて伸ばせる。

## 4. 保存安全性

既存の `App.runAtomicSaveMutation()` を維持して使用する。

- Rank・能力・価値更新
- 神鉄の鍛冶台1個消費
- 累計使用回数更新
- セーブ

上記を一括確定する。
セーブ失敗または処理例外時は、装備状態と神鉄所持数を処理前へ戻す。

## 5. セーブ互換

新しい保存項目は追加していない。
既存の装備インスタンス構造をそのまま使用するため、追加移行は不要。

過去版の神鉄で既に別装備へ変換済みの個体は、元の名称・固有特性を保存していないため、自動推測による復元は行わない。
誤った推測で別装備へ戻すことを避けるためである。

## 6. 正式マスター

`blacksmith_master.js` のスキーマを2へ更新し、以下を正式方針として登録した。

- `divineAnvilPreserveEquipmentIdentity: true`
- `divineAnvilPreserveNonScalableStats: true`

起動時上書きは行っていない。
